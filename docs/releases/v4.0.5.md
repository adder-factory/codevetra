# CodeVetra v4.0.5

Improves implementation queries and MCP evidence while fixing arithmetic and input boundaries.

## Changes

- Implementation queries prioritize production definitions over enum values,
  parameters, and historical fixtures while preserving exact leaf lookup.
- Symbol-impact requests accept `includeCommands=false`; conflicting file-mode
  options return actionable, privacy-safe argument errors.
- Context responses omit duplicated retrieval candidates by default while
  retaining source windows and provenance. `explain=true` includes the full trace.
- Path validation rejects hidden Windows drive prefixes; SCIP byte limits include
  protobuf headers; token estimates avoid overflow; extreme finite reranker
  scores normalize through wider arithmetic.
- Pinned Kani and Verus checks verify selected production contracts; Shuttle
  explores async cancellation and staging-barrier interleavings. All run inside
  enforced resource limits with explicit proof and scheduler coverage boundaries.
- Compatible Rust dependency updates include Jiff, tree-sitter, TOML editing,
  filesystem notifications, and refreshed native compression license notices.

## Upgrade

Run `codevetra upgrade --apply --project-path <PATH>` and restart existing owners.
Existing native generations remain compatible. Legacy names still require the
[migration guide](https://github.com/adder-factory/codevetra/blob/main/docs/CODEVETRA-MIGRATION.md).

**Compatibility:** native Rust and per-project RocksDB 11.12.0 remain the only runtime/storage path. RocksDB format v1 and generation contract V27 are unchanged.
