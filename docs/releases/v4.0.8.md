# CodeVetra v4.0.8

Delivers the biomarker and Rust relationship improvements from the unpublished
v4.0.7 candidate and corrects its Windows release build failure.

## Changes

- Counts each numeric source literal once, retains health counts above 65,535,
  and distinguishes exhaustive mappings, proof fixtures, and actionable duplication.
- Resolves bounded Rust `cfg` and literal `#[path]` modules, named Cargo targets,
  and proven qualified calls inside standard macro arguments.
- Describes mode-specific arguments and numeric limits in CLI/MCP schemas,
  with actionable field errors that omit private input values.
- Simplifies writer, replay, retention, and request ownership while preserving
  atomic publication, exact lease fences, cancellation, and retained completion.
- Reuses compatible Ubuntu build artifacts after workspace version changes
  and reduces empty-metric and ranked-result allocations.
- Uses Cargo response files for oversized Windows compiler invocations,
  preserving path privacy and validating the complete argument list in CI.

## Upgrade

Run `codevetra upgrade --apply --project-path <PATH>` and restart existing owners
and MCP hosts. Re-index source once for generation contract V35; native storage
format v1 remains compatible. Legacy names still require the
[migration guide](https://github.com/adder-factory/codevetra/blob/main/docs/CODEVETRA-MIGRATION.md).

**Compatibility:** Rust 1.100.0 and edition 2024; native Rust and per-project RocksDB 11.12.0; RocksDB format v1 and generation contract V35.
