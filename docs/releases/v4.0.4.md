# CodeVetra v4.0.4

Completes biomarker refreshes on larger graphs and accepts embedded-script health metrics in web components.

## Changes

- Biomarkers run through separately bounded input, reference, and clone stages,
  then evaluate at most 4096 document owners per storage request.
- Packed document identities, reference counts, and clone groups reduce retained
  memory within the existing workspace caps, preserving complete detector counts.
- All stages share one deadline and generation fence. Changed supporting inputs,
  cancellation, and failed stages cannot replace the published result.
- Concurrent computations cannot accumulate staged inventories; cached reads
  remain available while a refresh runs.
- Svelte, Vue, and Astro accept their embedded JavaScript, TypeScript, and TSX
  metrics with accurate source-detector coverage and original host-file locations.
- Unrelated language mismatches still fail validation. Duplicate document
  precedence and canonical clone representatives remain deterministic.

## Upgrade

Run `codevetra upgrade --apply --project-path <PATH>` and restart existing owners.
Refresh biomarkers with `codevetra admin biomarkers-refresh --project-path <PATH> --no-dry-run --confirm --database-query-timeout-ms 120000`.
Existing native source generations remain compatible; refresh recomputes the
changed detector contract. Legacy names still require the [migration guide](https://github.com/adder-factory/codevetra/blob/main/docs/CODEVETRA-MIGRATION.md).

**Compatibility:** native Rust and per-project RocksDB 11.12.0 remain the only runtime/storage path. RocksDB format v1 and generation contract V27 are unchanged.
