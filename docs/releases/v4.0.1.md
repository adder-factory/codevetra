# CodeVetra v4.0.1

This patch repairs project relocation and bounded storage and embedding workflows after the CodeVetra rename.

## Changes

- Recover a moved checkout with `codevetra relocate --from-project-path <OLD_PATH> --project-path <NEW_PATH>`, preserving its existing database identity and project state.
- Bound native scan pages by examined logical keys, including tombstones and unpublished records; index publication and graph reads continue across empty pages without exceeding their read limits.
- Resume embedding sweeps from the last document key instead of repeatedly scanning the corpus prefix, and avoid loading unused symbol summaries.
- Report `native_read_capacity_exceeded` separately from generation capacity so read failures do not suggest increasing the generation size limit.
- Configure `llm.embeddingLlm.embeddingBatchSize` from 1 to 128 when a provider needs smaller batches; the existing default remains 32.

## Upgrade

Run `codevetra upgrade --apply --project-path <PATH>`, then restart the MCP host.
Existing Cartograph installations must first follow the [name migration guide](https://github.com/adder-factory/codevetra/blob/main/docs/CODEVETRA-MIGRATION.md).
For a physically moved checkout, stop its storage owners and follow the guide's relocation procedure before reopening the host.

**Compatibility:** native RocksDB format v1 · generation contract V27; neither changes in this patch. Existing database and embedding-model identities are retained.
