# CodeVetra v4.0.0

Cartograph becomes **CodeVetra**: the executable is `codevetra`, MCP tools are
`codevetra_*`, and Rust packages are `codevetra-*`. This major release includes
an explicit migration that preserves existing RocksDB state and project policy.

## Changes

- Review now verifies supplied diff coordinates before attaching graph evidence,
  parses shrinking/header-shaped hunks correctly, and bounds compact responses.
- JS/TS code-health rules use operation-local AST evidence and publish rule
  coverage; compare results distinguish introduced, cleared, carried and changed findings.
- `navigate` adds exact cursor definition/reference/implementation lookup and bounded
  possible static JS/TS execution paths with nested guards, exits and explicit unknowns.
- Scoped Next.js/React Router navigation and supported HTTP, event, queue and
  observer relationships extend graph impact. Coverage and uncertain matches are explicit.
- Source packets prioritize requested bodies, report omissions, and offer optional
  client-acknowledged reuse with exact recovery and generation/hash validation.
- Rust receiver resolution, filtered graph traversal, retrieval diagnostics, pagination,
  status flags and oversized owner responses have regression coverage.
- Dependencies advance to `rust-rocksdb` 0.54.0 / RocksDB 11.12.0, with compatible
  Rust dependencies, pinned CI actions and Linux images refreshed.

## Upgrade

Install the new executable, stop the old host, and run `codevetra migrate-name --project-path <PATH>`.
Follow the [name migration guide](https://github.com/adder-factory/codevetra/blob/v4.0.0/docs/CODEVETRA-MIGRATION.md), reinstall managed registrations, reindex once, and restart the host.

**Compatibility:** RocksDB format v1 · generation V27 · Rust 1.99.1 / edition 2024. Prior state is preserved.
See the [dependency audit](https://github.com/adder-factory/codevetra/blob/v4.0.0/docs/v2/DEPENDENCY-UPDATE-2026-10-31.md) and [adapter coverage limits](https://github.com/adder-factory/codevetra/blob/v4.0.0/docs/MCP-USAGE.md#application-boundaries-and-navigation).
