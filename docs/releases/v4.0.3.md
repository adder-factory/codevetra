# CodeVetra v4.0.3

Keeps biomarker evidence current during obsolete-state cleanup and moves legacy state into real `.codevetra` directories.

## Changes

- Background removal of source-incompatible vectors and summaries no longer
  invalidates current biomarkers or rejects an otherwise valid in-flight refresh.
  Current input changes retain their generation and epoch fences.
- `migrate-name` physically renames preserved state, including the alias layout
  created by v4.0.0–v4.0.2, with owner and configuration admission held through the move.
- Migration preserves directory identity and permissions, refuses conflicting
  destinations, and resumes after interruption without initializing another index.
- Successful migration reports `placement: canonical`; the former `legacy_alias`
  result is retired because migration now creates a physical directory.
- Equal root ignore rules move to `.codevetraignore`; differing policies fail closed.
- Windows native storage accepts ordinary canonical project paths, including
  Rust's extended-path representation, without changing project identity.
- Fresh initialization no longer creates a `.cartograph` marker. Migration removes
  existing exact markers and requires retiring old executables before restarting hosts.

## Upgrade

Install v4.0.3, stop existing owners, and run `codevetra migrate-name --project-path <PATH>`.
Reinstall managed registrations and services with the new executable, restart hosts,
and refresh biomarkers. Follow the [migration guide](https://github.com/adder-factory/codevetra/blob/main/docs/CODEVETRA-MIGRATION.md) for project and shared model state.

**Compatibility:** native Rust with per-project RocksDB 11.12.0 remains the only runtime/storage path. RocksDB format v1 and generation contract V27 are unchanged.
