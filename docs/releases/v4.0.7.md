# CodeVetra v4.0.7

Improves code-health evidence, Rust relationships, and tool argument guidance while preserving native storage guarantees.

## Changes

- Retains health counts above 65,535 and distinguishes exhaustive mappings,
  independent proof fixtures, and actionable duplication without hiding raw metrics.
- Resolves bounded Rust `cfg` and literal `#[path]` modules, named Cargo targets,
  and proven qualified calls inside standard macro arguments. Ambiguous scopes,
  visibility restrictions, and macro overrides remain explicit.
- Describes mode-specific arguments and numeric limits in CLI/MCP schemas and
  returns actionable field errors without echoing private input values.
- Refactors writer, replay, retention, and request ownership while preserving
  atomic publication, exact lease fences, cancellation, and retained completion.
- Reduces empty-metric and ranked-result allocation, and strengthens bounded
  compiler-cache, test-runner, and formal-verification workflows.

## Upgrade

Run `codevetra upgrade --apply --project-path <PATH>` and restart existing owners
and MCP hosts. Re-index source once for generation contract V34; native storage
format v1 remains compatible. Legacy names still require the
[migration guide](https://github.com/adder-factory/codevetra/blob/main/docs/CODEVETRA-MIGRATION.md).

**Compatibility:** Rust 1.100.0 and edition 2024; native Rust and per-project RocksDB 11.12.0; RocksDB format v1 and generation contract V34.
